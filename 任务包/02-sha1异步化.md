# 任务：把同步的 SHA1 计算改成流式 + 异步

## 背景

启动器下载游戏资源时要校验 SHA1。当前实现有两个问题：

1. 用 `std::fs::read` 把**整个文件读进内存**再算（client.jar 有 20MB+）
2. 这个同步函数是在 `async` 任务里调的，8 并发时会把 tokio worker 阻塞住

## 现有代码

```rust
pub fn sha1_bytes(bytes: &[u8]) -> String {
    let mut h = Sha1::new();
    h.update(bytes);
    hex(&h.finalize())
}

pub fn sha1_file(path: &Path) -> Option<String> {
    let bytes = std::fs::read(path).ok()?;
    Some(sha1_bytes(&bytes))
}

fn hex(bytes: &[u8]) -> String {
    let mut s = String::with_capacity(bytes.len() * 2);
    for b in bytes {
        s.push_str(&format!("{b:02x}"));
    }
    s
}
```

调用处（这是一个 `async fn` 内部）：

```rust
} else if let Some(actual) = sha1_file(&task.path) {
    if actual.eq_ignore_ascii_case(&task.sha1) {
        return Ok(false);
    }
}
```

依赖环境：`tokio 1`（full）、`sha1 0.10`（`use sha1::{Digest, Sha1};`）。

## 需求

1. 新增 `pub async fn sha1_file_async(path: &Path) -> Option<String>`
   - 用 `tokio::task::spawn_blocking` 包住同步实现
2. 内部改成**流式**读取：`std::io::BufReader` + 固定缓冲区（建议 32KB）逐块 `update`，
   **不要**把整个文件读进 `Vec<u8>`
3. `sha1_file`（同步版）保留，但改成复用同一个流式实现
4. 优化 `hex()`：不要每个字节一次 `format!` 分配，改用 `write!` 写进预分配的 `String`
   （或用查表法）
5. **不引入新依赖**
6. 调用处改成 `sha1_file_async(&task.path).await`

## 输出

1. 完整的 `sha1_file` / `sha1_file_async` / 流式实现 / `hex` 代码
2. 调用处改法（一行）
3. 简短说明：为什么 `spawn_blocking` 里可以用 `std::io`？缓冲区大小怎么选？

**只要函数，不要输出整个文件。** 必须能通过 `cargo check`。
